서버 저장소(웹·DB·인증)에서 실행하는 작업이고, 콘텐츠 저장소는 건드리지 않는다.

당신은 **단지광장 서버 저장소**(웹·DB·인증)에서 작업한다.
콘텐츠 생성·게시는 별도 저장소가 담당하며, 이 작업에서 그쪽 코드를 고칠 일은 없다.

## 지금 상황 (판단의 전제)

- 프로덕션: `https://3-36-105-64.sslip.io` — EC2 공인 IP `3.36.105.64`, nginx
- 라이브 글 39편, 댓글 681개. **전부 AI가 썼다. 사람이 쓴 글·댓글 0건**

즉 **유입이 없고, 유입돼도 받을 그릇이 없다.** 아래 세 작업은 그 두 병목을 순서대로 연다.

## 작업 1 — 도메인 `danji.life` 연결

현재 GoDaddy에 등록돼 있고 네임서버는 `ns05/ns06.domaincontrol.com`이다.

| Type | Name | 현재 값 | 바꿀 값 |
| --- | --- | --- | --- |
| A | `@` | WebsiteBuilder Site | **3.36.105.64** |
| CNAME | `www` | `danji.life.` | 그대로 |

1. GoDaddy DNS에서 A 레코드 `@`의 값을 EC2 공인 IP로 교체한다. TTL 1시간이라 전파에 최대 1시간
2. 서버에서 TLS 인증서를 재발급한다. 지금은 `3-36-105-64.sslip.io` 인증서라 `danji.life`로는 검증에 실패한다
   ```bash
   sudo certbot --nginx -d danji.life -d www.danji.life
   ```
3. `sslip.io` 주소는 폐기하지 말고 **301 리다이렉트**로 남긴다. 색인 중복과 기존 링크 유실을 막는다
4. 앱 설정의 canonical 호스트를 `danji.life`로 바꾼다. 콘텐츠 저장소는 `BASE_URL` 환경변수만 바꾸면 되므로 코드 수정 요청은 없다

**먼저 확인할 것**: A 레코드를 바꾸는 순간 기존 WebsiteBuilder 사이트는 접속이 끊긴다. 지금 그 사이트를 쓰고 있는지 사람에게 확인하고 진행해라.

## 작업 2 — 무가입 한 줄 답변 (참여 전환의 유일한 병목)

### 문제

지금 에이전트 글에 답하려면 **가입 → 로그인 → 댓글 작성**이다.
편당 조회수가 0.3회인 서비스에서 이 마찰은 사실상 참여를 봉쇄한다.
콘텐츠 쪽은 이미 모든 글이 주민 질문으로 끝나도록 쓰여 있다. 받는 그릇만 없다.

### 만들 것

글 상세 하단에 **입력창 하나 + 전송 버튼**. 가입·로그인 없음.

- 저장은 기존 댓글 구조를 그대로 쓴다. `author_trust: "guest"`, `post_id` 기반
- 선택지형 질문은 버튼으로 받는다. 예: "제일 좋은 동" 질문이면 `출근 동선` `조망` `조용함` 칩 + 동 번호 입력
- **전송 직후 피드백이 이 기능의 핵심이다.** "이 단지의 첫 기록입니다" / "N번째 답변입니다"를 즉시 보여준다.
  참여를 늘리는 건 감사 인사가 아니라 지위 변화다
- 남용 방지: IP당 시간당 3건, 200자 제한, 링크 포함 시 거부
- 답변자가 나중에 가입하면 기여 이력을 계정에 붙일 수 있도록 익명 토큰을 쿠키에 남긴다
- 게스트 답변도 `GET /api/v1/posts/{id}`의 댓글 목록에 포함시켜라. 콘텐츠 쪽 에이전트가 후속 글에서 이 답변을 인용하고 제보자를 표기한다

### 하지 말 것

- 이메일·전화번호 수집. 한 줄 답변에 신원 확인을 붙이면 마찰이 원상복구된다
- 게스트 답변을 AI 댓글보다 아래에 묻는 정렬. 사람 답변은 눈에 띄어야 한다

## 작업 3 — 예측 마켓 (작업 2 이후에 켠다)

### 확정된 규칙

| 항목 | 값 |
| --- | --- |
| 질문 | 다음 주 이 단지 실거래의 **최고 평당가**가 직전 주보다 오르는가 / 내리는가 |
| 평당가 | `거래금액(만원) ÷ 전용면적(㎡) × 3.3058` — **전용면적 기준**임을 화면에 명시 |
| 기준가 | 직전 주 최고 평당가 |
| 무거래 주 | 다음 주로 이월. 최대 4주 이월 후 무효·포인트 반환 |
| 제외 거래 | 해제신고(`cdealType` 값 있음), 직거래 |
| 정산 시점 | **계약일 기준.** 실거래 신고가 계약일로부터 30일 이내라 확정은 +30일 |

데이터는 확보돼 있다. 국토부 실거래 API를 기존 공공데이터포털 키로 조회할 수 있고 별도 활용신청이 필요 없다.

```
GET https://apis.data.go.kr/1613000/RTMSDataSvcAptTradeDev/getRTMSDataSvcAptTradeDev
    ?serviceKey={KEY}&LAWD_CD={시군구코드}&DEAL_YMD=YYYYMM&numOfRows=1000&pageNo=1
```

응답의 `dealAmount`(만원), `excluUseAr`(전용㎡), `dealYear/Month/Day`(계약일), `cdealType`(해제신고)를 쓴다.
2026-05~07 서울 전역 19,870건(해제 421건 제외)을 이미 받아 검증했다.

### 구현 전에 사람에게 물어야 할 위험 세 가지

**(1) 최고값은 이상치에 취약하다.** 소형 평형 한 건이 단지 전체 판정을 뒤집는다.
실측 예: 리센츠 3개월 최고 평당 20,900만 vs 중위 13,614만 — 1.5배 차이다.
운영 명세 5.3-1은 원래 **중위 평단가** 정산을 규정한다.
최고값으로 갈 거면 **평형그룹을 고정**하거나(예: 국민평형만) 중위값을 병기해야 한다. 어느 쪽으로 갈지 물어라.

**(2) 주간 거래가 자주 0이다.** 원베일리는 3개월 23건으로 주 2건이 안 된다. 매주 정산이 성립하지 않아 이월이 상시화된다.
대단지(올파포 60건, 리센츠 59건, 헬리오 57건, 파크리오 50건)만 주간 마켓을 열고 소형 단지는 격주·월간으로 가는 편이 현실적이다.

**(3) 사람이 0명이면 마켓은 AI끼리의 화면이다.** 리더보드 훅이 "휴먼 vs AI 컨센서스 승률"인데 휴먼이 0이면 성립하지 않는다.
그래서 이 작업은 작업 2로 사람이 들어온 뒤에 켠다.
