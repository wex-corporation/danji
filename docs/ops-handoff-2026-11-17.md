# 운영 담당자 인계 — 콘텐츠 에이전트 작업 범위 규칙 적용 (2026-11-17 15:41 KST~)

대표님이 11/17 15:41에 작업 범위 규칙을 주셨다("최우선 · 다른 모든 지시보다 우선").
에이전트는 **이 저장소의 코드 변경**과 로컬 빌드·검사·피처 브랜치 커밋까지만 한다.
그래서 지금까지 에이전트가 직접 하던 일 가운데 아래 일들을 멈췄다.
규칙에는 "애매하면 서버 작업으로 본다"는 조항이 있다. 그래서 게시 API 호출과 공개 조회도 일단 멈춘 쪽에 넣었다.

| 멈춘 일 | 왜 범위 밖인가 |
| --- | --- |
| `publish.py`로 danji.life에 글·댓글 게시(`/api/v1/ingest/*`) | 운영 서버의 데이터를 바꾼다. 운영 DB에 직접 쓰는 것과 결과가 같다 |
| `market_vote.py --send`, `sync_personas.py --send` | 같은 이유(마켓 표·페르소나 명부를 운영 서버에 쓴다) |
| `.env`를 읽어 키 쓰기(`CIVIC_PULSE_API_KEY`·`KAPT_SERVICE_KEY`) | 시크릿 파일 열람이다. 공공데이터 API 조회(실거래·관리비·장충금·건축물대장)도 이 키가 필요해서 함께 멈췄다 |
| danji.life 인증서 확인(`openssl s_client`), stats·피드·글 상세 조회 | 운영 서버 상태를 직접 확인하는 일이다. 애매해서 범위 밖으로 봤다 |
| `build_daily_pack.py --day …` 검증 중 피드 조회(서모스탯·시차 검사) | 검증 단계가 운영 피드를 읽는다. 로컬만으로는 끝까지 돌지 않는다 |

에이전트가 계속 하는 일: 생성기 코드와 팩 JSON 작성, 캐시된 `data/` 자료로 계산하고 `assert` 걸기, 출고 검사(`shipping_audit.py --packs`, 로컬 파일만 읽는다), 문서, 피처 브랜치 `claude/danji-pipeline-patch-setup-csgpa1` 커밋·푸시.

## 1. 지금 걸려 있는 운영 작업 — 운영 담당자가 할 일

명령은 저장소 루트 기준이다. 키는 운영 담당자 쪽 `.env`에서 읽는다. 에이전트는 키 값을 보지도, 옮기지도 않는다.

### 1-1. 11/17 17:29 헬리오시티 글 게시 (오늘)

- 글: `daily-2026-11-17-helio-guard-step` — 시계열노트 「헬리오시티 경비비 8월분, 한 달에 2,532만원 줄었다」
- 팩: `content/daily-2026-11-17.json` (커밋 `9432b97`에서 작성, 검증·출고 검사 통과)
- 이 팩의 다른 두 편은 이미 나갔다. 13:17 그라시움 수선통장, 14:43 은마 건축물대장.

```bash
set -a && . ./.env && set +a
cd scripts
python3 build_daily_pack.py --day 2026-11-17      # 재검증. 피드를 읽어 서모스탯·시차를 다시 센다
python3 publish.py ../content/daily-2026-11-17.json --due --only daily-2026-11-17-helio-guard-step
```

- 게시 시각이 17:29라 `--due`는 그 뒤에만 보낸다
- 확인할 것은 셋이다.
  - 출력에 `unknowns …: 일치`가 나오는지
  - stats가 posts +1 · verified +1 · 생활 +1 · 댓글 +2로 늘었는지
  - 헬리오시티 피드에 댓글 2개(이단지만다른점·헬리오연가)가 보이는지
- 결과를 알려 주시면 에이전트가 `CLAUDE.md` 52번에 적는다

- 검증(피드 조회 포함)과 게시는 운영 담당자 몫이다. 명령은 1-1과 같고 `--day 2026-11-18`, `--only <id>`만 바꾼다

## 2. 걸려 있는 예약 작업 — 규칙과 충돌한다

아래 셋은 **울리면 게시·키 사용·운영 조회를 하라는 지시문**이다.
규칙이 우선하므로, 울려도 에이전트는 그 단계를 하지 않는다. 코드 쪽 할 일만 하고 이 문서를 갱신한다.

| `trig_014MtQZJwnBuXLYPDcNipMsK` 11/17 17:29 헬리오 슬롯·하루 보고 | 11/17 17:30 KST | 인증서·stats 확인 → 게시 → 피드 대조 |
| `trig_019FVCMM2XjDGtrxBDSKUczH` 매일 하루치 글 | 매일 09:23 KST | `.env` 확인 → 사람 반응 조회 → 자료 조회 → 게시 예약 |
| `trig_01K59RcmCqQCRiXQqjMDT5Q2` 목요일 장부 회차 | 11/19 15:41 KST | 발표 수집 → 마켓 표 전송 → 장부 글 게시 |

멈출지, 지시문을 '코드만'으로 바꿀지는 대표님이 정한다(3장).

## 3. 대표님께 여쭐 것

1. **콘텐츠 게시 API(`/api/v1/ingest/*`) 호출이 범위 밖이 맞는지.** 이 파이프라인의 마지막 단계라, 범위 밖이면 게시는 전부 운영 담당자가 한다
2. **공개 페이지·공개 API 조회(stats·피드, 읽기만)를 해도 되는지.** 안 되면 서모스탯·시차 검사를 로컬에서 끝낼 수 없다
3. **공공데이터 키(`KAPT_SERVICE_KEY`)를 쓰는 자료 조회를 누가 할지.** 에이전트가 못 하면 새 자료 축이 멈춘다. 지금은 캐시된 자료로만 쓴다
4. **예약 작업 셋을 멈출지**, 아니면 지시문을 '코드·문서만'으로 바꿀지
