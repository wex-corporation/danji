# 단지광장 — 글쓰기 기능 · 서비스 기능 · 글쓰기 품질 향상 체계

기준일 2026-10-09. 대표님 에이전트에게 넘기는 문서다. `docs/agent-brief-2026-10.md`를 먼저 읽었다고 가정한다.

- **글쓰기 기능**: 이 저장소. 조사하고, 글과 관점 댓글을 만들고, 검사해서 서버에 넣는다
- **서비스 기능**: 단지광장 본체. 별도 저장소, EC2, `danji.life`. 글을 보여 주고 사람이 참여하는 화면이다

둘은 인제스트 API 하나로만 이어진다. 품질을 올리는 일은 글쓰기 쪽에서 하지만,
**무엇이 품질인지는 서비스 화면이 정한다**(제목만 캡처되는 카드, 렌더링 안 되는 마크다운 등).

## 1. 글쓰기 기능 — 콘텐츠 엔진

### 1-1. 누가 쓰는가

"글을 쓰는 에이전트"는 두 겹이다. 품질을 올릴 때 어느 겹을 손대는지 구분해야 한다.

| 겹 | 실체 | 품질에 미치는 것 |
| --- | --- | --- |
| 저자 | Claude Code 세션(콘텐츠 에이전트) 하나. 조사하고 본문을 쓰고 검사한다 | 사실 정확성, 구조, 문장 |
| 목소리 | 페르소나. 글마다 배정하는 필명과 관점 (로컬 39 · 서버 76) | 말투, 관점의 다양성, 역할 경계 |

페르소나는 계층이 있다.
- 분석 13: 시황·세금·정책
- 홍보 22: 시설·생활권. 가격은 다루지 않는다
- 숫자비교표 1
- 팬 듀오 2
- 특이값 1

계층마다 쓸 수 없는 말이 다르다. 예를 들어 홍보 페르소나는 '억'·'시세'를 쓸 수 없다.

### 1-2. 부품

| 부품 | 파일 | 하는 일 |
| --- | --- | --- |
| 자료 수집 | `scripts/kapt_fees.py` · `kapt_complex_info.py` · `trade_volume.py` · `rent_volume.py` | 공공데이터포털 OpenAPI에서 관리비·단지정보·매매·전월세를 받아 `data/`에 캐시 |
| 무엇을 쓸지 | `scripts/gaps.py` | 서버 `/insights/gaps`를 운영 단지와 교집합해서 읽는다 |
| 생성기 | `scripts/build_*.py` (계열별 9개) | 특이값 · 주변 조사 · 분석 · 카드 · 홍보 · 탑5/20편 채우기 · 세금 · 팬 듀오 · 비교 |
| 게시 전 검사 | 생성기마다 `validate()` + `scripts/shipping_audit.py` | 규칙 위반 assert + 단지명을 가리고 바꿔 끼워도 되는 글 찾기 |
| 게시 | `scripts/publish.py` · `scripts/hide_posts.py` | 번들 전송, 숨김 처리 |
| 게시 후 감사 | `scripts/quality_audit.py` (10/9 신설) | 라이브 글 전체를 같은 루브릭으로 채점 |
| 기록 | `content/*.json` · `CLAUDE.md` 6장 · `data/quality/` | 게시 원본, 사고와 규칙의 이력, 품질 기준선 |

### 1-3. 한 편이 나가는 길

```
gaps 조회 → 자료 조회(출처 URL·확인일 기록) → 생성기에서 본문·제목·요약·댓글 작성
  → validate() ─┐
  → 출고 검사 ──┼─ 하나라도 걸리면 고쳐서 다시
  → 샘플 2~3편 사람 읽기 ─┘
  → publish.py → stats·피드 증가분 대조 → content/에 팩 커밋
```

한 편은 글 하나와 관점 댓글 2개 이상이다.
- **글 필드**: 단지, 페르소나, 분야, 제목, 요약, 본문, 출처 등급, 출처 목록, 출처 노트, 게시 시각
- **댓글**: 다른 페르소나가 단다

## 2. 서비스 기능 — 단지광장 본체 (화면에서 확인, 10/9)

코드는 볼 수 없어서 공개 화면과 공개 API로 확인한 것만 적었다.

| 화면 | 기능 |
| --- | --- |
| 지도 홈 | 단지 핀(글 수), 아파트·지역 검색, 시군구 필터, 내 주변, 실시간 순위, 정렬(글 많은 순·새 글 순·이름 순) |
| 단지 광장 | 분야 필터(거래·정책·전월세·생활·세금), 정렬(추천순·최신순·관점 많은 순), 글 카드(페르소나명·`AGENT`·`✓ 출처 확인`·조회·좋아요), 카드에서 바로 댓글, 많이 본 글, 옆 단지로 이동 |
| 주민 투표 | "이번 주 ○○ — 사는 사람들은 어떻게 볼까요" 오른다/내린다. 10/9 원베일리 기준 0표 |
| 글쓰기 | **비회원 가능**(닉네임 + 삭제용 비밀번호, IP 앞자리 표시). 유형: 일반·질문·투표·나눔 |
| 글 상세 | `확인 기준` 상자(출처 노트 + 원문 링크), 관점 댓글, **한 줄 답변**("사시는 분만 아는 게 있습니다", 가입 없이 등록), 공유·저장·신고, 글마다 공유 카드 이미지 |
| 실거래가 탭 | 서버가 직접 집계: 최근 거래, 1년 거래 수, ㎡당 평균, 해제 신고 제외, 평형별 최근 거래·최저~최고 |
| 단지 정보 탭 | K-apt 기본정보(주소·동수·층수·사용승인·난방·주차·관리사무소 전화·평형 구성) |
| 위키 탭 | 반복 질문(주차 등록·분리수거 요일 등) 모음. 편집은 로그인 + 거주 인증, 이력 공개 |

**신뢰 표시는 두 축이다**(`docs/ingest-api.md` 10-1).

| 축 | 누가 정하나 | 값 |
| --- | --- | --- |
| 글의 출처 | 우리가 정한다 | `verified`(출처 확인) · `opinion`(주민 의견) · `pending`(검증 대기) |
| 글쓴이 | 서버가 정한다 | `ai` · 비회원 · 회원 · 인증 주민 |

**AI는 사람 등급을 주장할 수 없다.**

**정렬 점수** = 신선도(반감기 18시간) + 참여도(조회·공감·댓글) + 출처 가산(verified +18).

**서비스 쪽에서 지금 걸려 있는 것**
- 글 페이지가 전부 `noindex`다
- 사이트맵이 7개 주소(홈 + 단지 6)뿐이다
- 단지 5곳이 사라졌다
- **글 23편의 관점 댓글이 서버에서 사라졌다**(아래 4-2)

## 3. 두 기능의 접점 — 한쪽이 바뀌면 다른 쪽 규칙이 바뀐다

| 서비스의 사실 | 글쓰기 쪽 규칙 |
| --- | --- |
| 공유 카드에 **제목만** 들어간다. 34자를 넘으면 잘린다 | 제목 34자, 후킹은 제목에서 |
| 마크다운이 렌더링되지 않는다 | `**` 금지 |
| `summary`가 검색·공유 설명문이 된다 | 첫 문단이 혼자 읽혀야 한다 |
| 정렬이 신선도 반감기 18시간 | 하루에 몰아 올리지 않는다(서모스탯) |
| 같은 `external_id` 재전송 = 수정 | 결함 글은 지우지 않고 고쳐서 다시 보낸다 |
| **글 상세 API가 호출마다 조회수 +1** (10/9 확인) | 감사 도구는 상세 API를 반복 호출하지 않는다 |
| 날짜가 UTC로 온다 | 하루 편수는 KST로 센다 |
| 한 줄 답변·비회원 글쓰기·위키가 있다 | 글 끝 질문은 **한 줄로 답할 수 있는 질문**이어야 한다 |

서비스가 바뀌면 이 표부터 갱신한다. 8/21 화면 점검 전까지 `**`가 13곳에서 별표로 노출되고 있었다.

## 4. 글쓰기 품질 향상 체계

### 4-1. 품질의 정의 — 루브릭

자동 검사 항목은 `scripts/quality_audit.py`와 ID가 같다.

**하드 규칙 (하나라도 걸리면 결함)**

| ID | 항목 | 기준 |
| --- | --- | --- |
| Q1 | 출처 | `verified` 글에 출처가 있다 |
| Q2 | 사실/해석 분리 | 사실 글에 "여기서부터는 해석입니다" 같은 전환 문장이 있다 |
| Q3 | 질문으로 닫기 | 본문이 주민에게 던지는 질문으로 끝난다 |
| Q4 | 제목 | 34자 이내 |
| Q5 | 마크다운 | `**` 없음 |
| Q6 | 금지 표현 | 출처 불명("알려져 있다")·경험 창작("제가 살아보니")·투자 지시·담합 유도·학군 서열·우열 비교·말미 고지 |
| Q7 | 조사 | 단지명 뒤 은/는·이/가·을/를, 숫자 단위 뒤 로/으로 |

**경고 (결함은 아니지만 품질 신호)**

| ID | 항목 | 기준 |
| --- | --- | --- |
| W1 | 낡은 시점 표현 | 14일 넘은 글에 "오늘·이번 주·지난주"가 남아 있다 |
| W2 | 문말 단조 | `~니다.` 문장이 8번 이상 연속된다 |
| W3 | 관점 댓글 부족 | 화면에 보이는 AI 댓글이 2개 미만 |
| W4 | 다른 글과 유사 | 단지명·숫자를 가린 뒤 어절 유사도 0.35 이상 |
| W5 | 댓글 돌려쓰기 | 같은 댓글 문장이 여러 글에 달렸다 |
| W6 | 출처 확인일 | 출처·노트에 확인·조회 날짜가 없다 |
| W7 | 체험 어투 | "하더군요·더라고요". 자료를 읽고 한 말인지 사람이 문맥으로 판정 |
| W8 | 댓글 유실 | 보낸 댓글보다 화면 댓글이 적다 |

**사람이 판정하는 항목 (자동화가 안 된다)**

| ID | 항목 | 질문 |
| --- | --- | --- |
| H1 | 사실 정확성 | 본문 숫자를 원자료로 다시 맞춰 보면 같은가. 순위 주장("가장 높다")은 전 단지 기준에서도 맞는가 |
| H2 | 질문의 질 | 거기 사는 사람이 한 줄로 답할 수 있는가. 답이 다음 글의 재료가 되는가 |
| H3 | 고유성 | 이 단지에서만 나올 수 있는 이야기인가 |
| H4 | 제목 | 공유 카드에 제목만 떴을 때 누르고 싶은가 |
| H5 | 목소리 | 그 페르소나의 역할·말투에 맞는가. 역할 경계를 넘지 않았는가 |

### 4-2. 기준선 — 2026-10-09 라이브 145편

```
하드 규칙 무결함 125편 (86%)
Q2 5 · Q3 3 · Q4 14 · 나머지 0
W1 13 · W2 61 · W3 23 · W6 39 · W7 2 · W8 23 · W4·W5 0
반응: 공감 0 · 도움돼요 0 · 사람 댓글 1
```

**게시 시기별 하드 결함 비율 — 규칙이 생긴 뒤로 해당 결함이 사라진다**

| 시기 | 글 | 하드 결함 | 주된 결함 |
| --- | ---: | ---: | --- |
| ~8/16 초기 | 27 | 26% | 질문으로 안 닫음, 34자 초과, 낡은 시점 표현 |
| 8/17~8/20 특이값·주변 | 15 | 60% | 34자 초과 9편(34자 규칙은 8/21에 생겼다) |
| 8/21~8/23 카드·홍보·20편 | 85 | 5% | 해석 전환문 누락 4, 확인일 누락 36 |
| 9/26~9/27 세금 | 18 | **0%** | 문말 단조 16 |

**아직 안 잡힌 것은 W2(문말 단조)다.** 모든 시기에 남아 있고 최신 팩에서도 18편 중 16편이다.

**사람 반응은 1건뿐이다.** 비회원 '펠릭스'가 8/24에 팬 듀오 첫 글(AI가 원베일리를 좋아한다고 고백하는 글)에 "ㅎㅎㅎㅎ 잼있는 친구네"라고 달았다.
- 데이터 글이 아니라 캐릭터 글에 달렸다
- 표본이 하나라 결론을 내리지 않는다
- **6주째 답이 없다.** 사람 반응에 응답하는 고리가 아직 없다는 뜻이다

**조회수는 지표로 쓸 수 없다.** 글 상세 API가 호출마다 +1이라 우리 감사 도구가 조회수를 부풀려 왔다.
- 8월 출고 검사 실행분이 섞여 있다
- 10/9 감사 개발 중에도 약 290이 올랐다
- 지금 `quality_audit.py`는 본문을 로컬 팩에서 읽어 실행당 +5 안팎으로 줄였다
- 서버에 "에이전트 조회는 세지 않기"를 요청해야 한다

### 4-3. 루프 — 매 배치마다

```
① 게시 전 게이트   validate() + 출고 검사 + 샘플 사람 읽기(H1~H5)
② 게시 후 감사     quality_audit.py — 주 1회, 결과는 data/quality/<날짜>.json
③ 결함 → 규칙      새 결함 유형은 세 군데에 동시에 넣는다
                     a. CLAUDE.md 6장 이슈로 기록(무슨 일이, 왜, 어떻게 막았나)
                     b. 생성기 validate()에 자동 검사 추가
                     c. quality_audit.py에 항목 추가(라이브 재발 감시)
④ 라이브 수정      결함 글은 같은 external_id로 고쳐 재전송(멱등키 버전 +1), 못 고치면 hidden
⑤ 반응 읽기        사람 댓글·한 줄 답변·좋아요. 생기면 그 글의 무엇이 달랐는지 기록하고 응답한다
```

**원칙: 같은 결함을 사람이 두 번 잡지 않는다.** 한 번 사람이 찾은 결함은 다음부터 기계가 잡아야 한다.

### 4-4. 이 루프가 실제로 돈 기록

| 사고 | 규칙이 된 것 |
| --- | --- |
| 제목에 "아리팍는", "그라시움는" | `J()` 조사 헬퍼 (받침 판정) |
| "47명로", "수선비으로" | `JR()` 로/으로 헬퍼, `BAD_RO` 정규식 |
| `**강조**`가 화면·공유 카드에 별표로 노출(13곳) | `**` 금지 |
| 공유 카드 제목 잘림 | 제목 34자 |
| 템플릿에 단지만 바꿔 끼운 글 65편 반려 | 출고 검사 + 단지별 특이값에서 글을 시작하는 생성기 |
| "5곳 중 최고"가 11곳 기준으로 세 번 무너짐 | 순위 주장은 전 단지 캐시로 재검증 |
| 같은 날 한 단지에 3편(팩마다 자기 팩만 셈) | 게시된 피드와 합쳐 세는 `published_today()` |
| 그 함수가 UTC로 하루를 셈(생성기 8곳에 복사) | `kst_day()` |
| 세법 개정안을 시행법으로 착각할 뻔함 | 조문·국회 자료 먼저 |
| AI 페르소나 댓글 "실제 상담에서도 …하더군요" | 경험 창작 금지 항목, W7 |
| 방침을 바꿨는데 토픽 요약이 옛 방침 그대로 | 방침 변경 시 토픽·meta·docstring 동시 수정 |
| 감사 도구가 조회수를 부풀림 | 본문은 로컬 팩에서 읽는다 |

### 4-5. 다음 개선 과제 — 우선순위 순

1. **이미 나간 결함 글 고치기.** 같은 `external_id`로 재전송하면 수정이 되니 안전하다. 게시 키가 필요하다.
   - W8 댓글 유실 23편: 보낸 댓글을 다시 보낸다
   - Q3 3편 · Q2 5편: 문장 보강
   - W1 13편: "이번 주" 같은 말을 날짜로 바꾼다
   - Q4 14편: 제목 34자 초과. **제목을 바꾸면 이미 공유된 카드와 달라지니** 운영자 확인 후 진행
2. **W2 문말 단조.** 가장 넓게 남은 결함(61편)이다. 생성기 프레임마다 다른 방식으로 문말을 깬다.
   같은 윤문 규칙을 일괄 적용하면 문체가 수렴해 출고 검사 유사도가 오른다(`CLAUDE.md` 15번)
3. **W6 확인일.** 출처 노트에 조회일을 쓰는 걸 모든 생성기 `validate()`에 넣는다
4. **검사 코드를 한 곳으로.** 금지어 목록·`J()`·`published_today()`가 생성기 9개에 복사돼 있다.
   UTC 버그가 8곳에 동시에 있었던 이유다. `scripts/` 공용 모듈로 합친다
5. **독립 검수자.** 쓴 에이전트가 자기 글을 검수하면 같은 맹점을 공유한다.
   다른 에이전트가 H1~H5로 매 배치 샘플을 읽는다. 대표님 에이전트가 맡을 수 있다(5장)
6. **사람 반응에 응답하기.** 명세 6장의 응답 규칙이 아직 구현돼 있지 않다.
   펠릭스 댓글처럼 사람 반응이 오면 그 단지의 페르소나가 답하는 경로가 필요하다
7. **소재 재고.** 품질의 상한은 자료다. K-apt 축은 3라운드에서 고갈됐다.
   - 9월 실거래 갱신: `KAPT_SERVICE_KEY` 재발급 필요
   - 공시가격: 국내 회선에서 1회 조회

## 5. 대표님 에이전트의 역할 제안 — 독립 검수자

글쓰기 에이전트(이 저장소)는 만들고 고친다. 대표님 에이전트는 **다른 눈으로 읽고 알린다.**

**할 수 있는 것**
- 저장소를 받으면: `data/quality/` 최신 결과를 읽어 주간 품질 보고를 대표님께 올린다
  - 직접 돌리려면 `python3 scripts/quality_audit.py`. 키가 필요 없다
- 라이브 글을 H1~H5로 읽는다. 매주 단지마다 최신 글 2편씩
  - 공개 페이지나 목록 API로 읽는다
  - **글 상세 API를 반복 호출하지 않는다**(조회수 오염)
- 슬랙·드라이브의 기획 결정이 루브릭과 어긋나면 알린다. 예: 새 메뉴, 새 글 유형
- 사람 반응이 생기면 바로 알린다. 지금까지 1건이다

**결함 보고 양식** — 이 형식이면 글쓰기 에이전트가 바로 규칙으로 바꿀 수 있다

```
글: https://danji.life/c/{slug}/p/{id}  (external_id 알면 함께)
항목: H1 사실 정확성
문제: 본문 "11곳 중 가장 높다" — 같은 캐시에서 리센츠가 더 높음
근거: data/mgmt-fees/... 또는 원자료 URL
제안: 순위 표현 삭제 또는 "2번째"로
재발 방지 아이디어(있으면): 순위 주장에 비교군 크기를 함께 쓰게 강제
```

**하지 않을 것**
- 직접 게시·수정하지 않는다. 고치는 건 글쓰기 쪽에서 검사를 거쳐 한다
- 키를 문서·채팅에 적지 않는다
- 숨김 글을 되살리자고 제안할 때는 숨긴 이유부터 확인한다(`CLAUDE.md` 6장)
