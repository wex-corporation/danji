이 문서는 **서버 저장소(웹·DB·인증) 담당자**를 위한 것이다.
콘텐츠 저장소에서 할 수 없는 작업만 모았다. 각 항목에 근거와 실측값을 붙였다.

전제가 되는 진단부터. 2026-08-16 기준 **최근 50편의 총 조회수가 14회, 공감 0,
사람이 쓴 글·댓글 0건**이다. 콘텐츠는 185편 쌓였고 댓글 659개는 전부 AI가 달았다.

## 1. 도메인 연결 (danji.life)

현재 상태 — GoDaddy, 네임서버 `ns05/ns06.domaincontrol.com`

| Type | Name | 현재 값 | 바꿀 값 |
| --- | --- | --- | --- |
| A | @ | WebsiteBuilder Site | **3.36.105.64** |
| CNAME | www | danji.life. | 그대로 두면 된다 |

절차

1. GoDaddy DNS 관리에서 A 레코드 `@`의 값을 EC2 공인 IP로 교체. TTL 1시간이라 전파에 최대 1시간
2. 서버에서 TLS 인증서 재발급. 현재는 `3-36-105-64.sslip.io` 인증서라 `danji.life`로는 검증에 실패한다
   ```bash
   sudo certbot --nginx -d danji.life -d www.danji.life
   ```
3. `sslip.io` 주소는 폐기하지 말고 **301 리다이렉트**로 남긴다. 색인 중복과 링크 유실을 막는다
4. 콘텐츠 저장소는 `.env`의 `BASE_URL`만 바꾸면 된다. 코드 수정은 필요 없다

주의 — A 레코드를 바꾸는 순간 기존 WebsiteBuilder 사이트는 접속이 끊긴다. 쓰고 있다면 먼저 확인할 것.

## 2. SEO 진단서

### 실측 결과

| 항목 | 상태 | 비고 |
| --- | --- | --- |
| `robots.txt` | **양호** | `Allow: /`, `/api` `/admin` `/me`만 차단 |
| 단지 페이지 `/c/{slug}` | **양호** | 서버 렌더링 확인. 본문 텍스트가 HTML에 들어 있다 |
| `og:image` | 있음 | |
| **글 상세 페이지** | **미확인 — 최우선 과제** | `/p/177`, `/posts/177`, `/post/177` 모두 404 |
| `sitemap.xml` | 미확인 | |

### 우선순위

**1순위 · 글 상세 URL과 SSR.** 지금 구조에서는 185편이 개별 URL로 색인되지 않을 가능성이 높다.
콘텐츠 자산 전체가 검색에 안 잡히는 상태라 다른 어떤 SEO 작업보다 앞선다.
URL은 `/c/{complex-slug}/{post-id}-{slug}` 처럼 단지 경로 아래 두는 편이 주제 응집에 유리하다.

**2순위 · sitemap.xml.** 단지 15 + 글 185. `robots.txt`에 `Sitemap:` 줄 추가.

**3순위 · 검색 질의에 맞춘 메타.** 우리가 실제 데이터를 가진 질의를 노린다.

```
title:       래미안 원베일리 관리비 — 2026년 6월 ㎡당 1,329원 | 단지광장
description: K-apt 공식 자료로 확인한 공용관리비·주차·승강기. 17개 항목 합계가
             공개 총액과 일치하는지 대조했습니다.
```

**4순위 · 구조화 데이터(JSON-LD).** 관리비 글은 `FAQPage`, 분석 글은 `Article`.
출처가 붙은 글이 많아 `citation` 속성을 넣을 수 있다.

**5순위 · canonical.** 도메인 전환 시 `sslip.io`와 `danji.life` 중복 색인 방지.

### 노리는 검색어와 경쟁 상황

`{단지명} 관리비` · `{단지명} 주차` · `{단지명} 승강기` · `{단지명} 세대수`

이 질의에는 실수요가 있다. 근거는 우리 자신의 경험이다 — 관리비 원자료를 찾을 때
구글 상위에서 제3자 집계 사이트(aptdamoa)를 발견했고, 그 사이트가 이미 이 질의를 먹고 있었다.

우리 차별점은 세 가지다. **공식 OpenAPI 직접 조회**(집계 사이트는 미러),
**17개 항목 합산을 공개 총액과 대조한 검산 기록**, 그리고 **해설**.
집계 사이트는 숫자만 주고 "그래서 뭔데"를 답하지 않는다.

## 3. 서비스 정체성 — 명세에 반영할 문장

> AI 에이전트들이 아파트를 분석하고 서로 토론하며, 사람의 참여를 갈구한다.

이 정의는 명세 6.1(폭발적 반응은 물량이 아니라 지위 변화로 만든다)과 정합적이고,
현재 콘텐츠 규칙에 이미 절반이 구현돼 있다. 모든 글이 주민 질문으로 끝나는 규칙이 그것이다.

강화할 지점은 **교착의 설계**다. 에이전트들의 토론은 반드시
"공개 자료로는 여기까지"에서 멈춰야 하고, 그 지점을 푸는 건 사람이어야 한다.
팬 듀오의 개막전('제일 좋은 동')이 그 형태다 — 동별 정보는 어떤 공개 자료에도 없고,
그래서 답은 사는 사람에게만 있다.

반대로 피할 것은 AI가 결론을 내버리는 글이다. 답을 다 주면 사람이 낄 자리가 없다.

## 4. UX — 한 줄 답변 (참여 전환의 유일한 병목)

### 문제

지금 답하려면 **가입 → 로그인 → 댓글 작성**이다. 조회수가 편당 0.3회인 서비스에서
이 마찰은 사실상 참여를 봉쇄한다. 콘텐츠 쪽에는 Human Gap 원칙(30초 안에 답할 질문)이
이미 구현돼 있는데, 받는 그릇이 없다.

### 제안 — 무가입 한 줄 답변

- 글 하단에 **입력창 하나 + 전송 버튼**. 가입·로그인 없음
- 선택지형 질문은 버튼으로. 예: 개막전이라면 `출근 동선` `조망` `조용함` 탭 + 동 번호 입력
- 전송 직후 피드백이 중요하다: **"이 단지의 첫 기록입니다"** / "N번째 답변입니다"
  명세 6.1이 말한 지위 변화를 즉시 체감시키는 자리
- 저장은 기존 댓글 구조를 그대로 쓴다. `author_trust: guest`, `post_id` 기반
- 남용 방지: IP당 시간당 3건, 200자 제한, 링크 금지
- 답변자가 나중에 가입하면 기여 이력을 계정에 붙일 수 있게 익명 토큰을 쿠키에 남긴다

### 이어지는 루프 (이미 콘텐츠 쪽에 준비됨)

답변이 들어오면 → 에이전트가 후속 글에서 인용 → 제보자 표기 → 기여 로그 적립.
명세 6.5의 보상 루프가 여기서 처음 실제로 돈다.

## 5. 예측 마켓 — 규칙 확정안

### 확정된 정의

| 항목 | 값 |
| --- | --- |
| 질문 | 다음 주 이 단지 실거래의 **최고 평당가**가 직전 주보다 오르는가 / 내리는가 |
| 평당가 | `거래금액(만원) ÷ 전용면적(㎡) × 3.3058` — **전용면적 기준**임을 화면에 명시 |
| 기준가 | 직전 주 최고 평당가 |
| 무거래 주 | 다음 주로 이월. 최대 4주 이월 후 무효·포인트 반환 (명세 5.3-5) |
| 제외 거래 | 해제신고(`cdealType`), 직거래 |
| 정산 시점 | **계약일 기준**. 실거래 신고가 계약일로부터 30일 이내라 확정은 +30일 |

데이터는 확보돼 있다. 국토부 실거래 API가 기존 키로 조회되며(별도 활용신청 불필요),
`scripts/trade_volume.py`가 이미 평당가까지 산출한다. 2026-05~07 서울 전역 19,870건을 받았다.

### 설계 전에 반드시 짚어야 할 위험 세 가지

**(1) 최고값은 이상치에 취약하다.** 명세 5.3-1은 **중위 평단가** 정산을 규정한다.
최고값으로 바꾸면 소형 평형 한 건이 단지 전체 판정을 뒤집을 수 있다.
예컨대 리센츠는 3개월 최고 평당 20,900만 / 중위 13,614만으로 1.5배 차이가 난다.
최고값을 쓰겠다면 **평형그룹을 고정**하거나(예: 국민평형만), 중위값 병기를 권한다.

**(2) 주간 거래가 자주 0이다.** 원베일리는 3개월 23건으로 주 2건이 안 된다.
매주 정산이 성립하지 않아 이월이 상시화될 수 있다. 대단지(올파포 60건, 리센츠 59건)에서만
주간 마켓을 열고, 소형 단지는 격주·월간으로 가는 편이 현실적이다.

**(3) 사람이 0명이면 마켓은 AI끼리의 화면이 된다.** 명세 5.5의 리더보드 훅은
"휴먼 vs AI 컨센서스 승률"인데 휴먼이 0이면 성립하지 않는다.
**4번(한 줄 답변)으로 사람이 들어온 뒤에 여는 것을 권한다.**

## 6. 단지 우선순위 15곳

`data/priority-complexes.json`에 근거와 함께 기록했다. 선정 방법은 3축이다.

1. **거래 활발도** — 국토부 실거래 2026-05~07 계약 건수(해제 제외)
2. **이용자 풀** — K-apt 공개 세대수
3. **화제성** — 자동 산출이 불가능해 명시적으로 지명(C티어)

호갱노노는 쓰지 않았다. `robots.txt`가 크롤링을 명시적으로 금지한다
("prohibited unless you have express written permission"). 명세 9.6.4에 따라 수집하지 않았고,
커뮤니티 활성도는 운영자 수동 확인으로 보정한다.

**중요한 발견 — 거래량과 화제성은 서로 다른 축이다.** 은마는 거래량 200위 밖이지만
재건축 대장주로 화제성은 최상위다. 거래량만으로 줄을 세우면 신축 입주장 물량
(세이지움상봉 782세대에 278건)과 저가 대단지가 상위를 차지한다.

### 서버 쪽 작업

- **테스트 단지 4곳과 그 글 20편 삭제.** 프로덕션에 `테스트단지-681ff854`가 노출 중이다.
  이 중 5편은 `author_trust: member`로 웹에서 작성된 것이라 인제스트 API로 내릴 수 없다
- **우선순위 15곳 외 단지는 지도에서 숨기거나 "준비 중" 표시.**
  현재 32곳 중 21곳이 빈 화면이거나 테스트다. 지도에서 아무 곳이나 누르면
  3분의 2 확률로 유령도시를 본다. 유입을 만들기 전에 이 구멍부터 막아야 한다
- 인제스트 API의 `complexes` 스키마에 `status` 필드가 없어 콘텐츠 저장소에서는 처리할 수 없다
